## 🗂️ Standardized Project Folder Structure

Every project folder within this repository adheres to a standardized hierarchy:

```
[Project_Folder]/
├── deliverables/        # ⭐ FINAL CLIENT DELIVERABLES (PDFs, PPTXs, DOCXs, Map Sheets)
├── drafts_and_working/  # Earlier revision stages, editable source files, and working drafts
├── photos_and_assets/   # High-resolution ground and drone imagery (.DNG, .JPG)
├── scripts/             # Python automation pipelines, WhiteboxTools, and rendering code (where applicable)
├── archive/             # Immutable zip backups of original field packages
└── README.md            # Detailed project summary, deliverable tables, and technical specs
```

## 🛡️ Data Integrity, Versioning & Quality Assurance

* **Verified Final Deliverables:** When multiple draft versions existed during project delivery cycles, the final delivered asset has been verified based on client sign-off timestamps, presentation slide completeness, and resolution.
* **Archival Preservation:** Earlier working iterations are systematically archived in `drafts_and_working/` or `archive/` folders. **No data has been discarded or overwritten.**
* **GIS Spatial Consistency:** All geospatial layers adhere to standard projection systems (**WGS 84 / UTM Zone 43N - EPSG:32643** where projected) with verified topological integrity.
* **Clean GitHub Repository:** Includes a tailored [`.gitignore`](./.gitignore) preventing temporary Office lock files (`~$*.pptx`, `~$*.docx`) and Python caches from cluttering version control.
